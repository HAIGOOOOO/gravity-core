### 0. 新しく足した事（版 5）: AI っぽさを消す
- 持ち主の言葉:「AI っぽい UI やデザインが多く見られる」。担当 C と D は、**題目 0「AI っぽさを消す」**（`docs/tasks/題目0_AIっぽさ.md`）を、突き返しの次、自分の担当の題目より先にやる。
- **調べ物は妥協しない**（30 件以上、見分け方 20 項目以上）。調べた結果を、自分の場所の今の物の検品と直しに使い、この先の全部の題目の審査で使う。
- **サブエージェントは、1 つの担当で同時に 1 体まで**（担当の AI 本人＋1 体）。審査役の 2 つの役も 1 体ずつ順番に。

### 1. 3 本の枝が、それぞれゲームを一通り全部作る
- 担当 B・C・D の 3 本の枝（`team-b` `team-c` `team-d`）は、それぞれが**ゲーム全体**を作ってよい。リーダーは、場所ごとに一番良くできた枝の物を選んで本線に取り込む（例: 天体の絵は D の枝、揺れは C の枝）。
- そのため、**場所ごとのフォルダ分けと、部品の形（`src/contracts/`）は崩さない。** ほかの枝の物と組み合わせても動くようにする。
- 触ってはいけないのは、リーダーの場所だけ（`AGENTS.md` 1 章）。

### 2. やる順番（全員共通。上から順に）
1. **リーダーの突き返し**（`docs/review/<担当>.md`）。その次に **題目 00「脳汁」**（版 6 から）、その次に **題目 0「AI っぽさを消す」**（版 5 から）。どちらも担当 C・D。提出したら 2 へ
2. **自分の担当**の題目（`docs/tasks/<担当>.md`）。リーダーが全部の題目に「合格」を出すまで。返事を待っている間も、自分の担当の一番弱い題目を磨き続ける。
3. 自分の担当が全部合格したら、**ほかの担当の場所**。どこをやるかは `docs/review/<担当>.md` の「次にやる場所」に、リーダーが書く。書かれていなければ、ほかの担当の手順書のうち、まだ合格していない題目を選ぶ。
4. **頼まれた調べ物**（`docs/tasks/<担当>.md` の最後の「調べ物」）。2 の題目を 1 つ提出するたびに、1 つ進めてよい。

**手を空けない。** 「全部終わった」と止まらない。終わったと思ったら、一番弱い所をもう一周する。

### 3. 担当の重み
- **D（たいち）**: 形と色。止まっている時の見た目の全部（天体の絵、盤面、照準の形、全画面、文字）。
- **C**: 動きと手応え。起きた事への反応の全部（演出、画面の揺れ、ヒットストップとスロー、天体の潰れと弾み、得点の飛び方、画面やボタンの動き）。
- **B**: 続ける。再生、図鑑、日替わり、記録、共有（人はまだいない）。
- 持ち主が特にこだわってほしいのは、**見た目と手応え**です。

### 4. 音はやらない
- 音（効果音・曲）は、持ち主とリーダーが本物の音を元に作る。**音を作る・直す作業はしない**（`src/audio/` は触らない）。
- 音について頼まれているのは、調べ物だけ（担当 C の手順書の最後）。

### 5. 手応えの設計図
- `docs/手応え.md` に、手応えの考え方・4 つの階級・時間の決まり・担当ごとの一覧をまとめた。C と D は必ず読む。

### 6. 時間を止める・遅くする
- ヒットストップとスローは、演出の部品の `timeScale()` で頼める（`src/contracts/app.ts` の `EffectsLayer`）。上限はリーダーの側でかかる（`src/shared/time.ts`）。
