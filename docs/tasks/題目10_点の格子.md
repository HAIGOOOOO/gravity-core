# 題目 10「点の格子の盤面」（D）と 題目 11「点の動き」（C）

2026-11-17 リーダー。方針の版 10。決まりは `docs/design/DESIGN.md`（先に全部読む）。

## 0. なぜやるか
- 持ち主が今のゲームを見て「仕組みやルールはうまくいってるけど、AI で適当に作った感じが出てる」。
- 原因（リーダーの見立て）: 見た目を部品の数と AI の審査役の点数で決めていて、人の目で選んでいなかった。足すだけで、何も捨てていなかった。
- だから今回は「絵の案 → 持ち主が選ぶ → 作る → 人の目で合否」の順を守る。部品の数・層の数・審査役の点数を、良さの基準にしない。

## 1. 題目 10（D）: 盤面の静止画の案 3 つ（期限 11/19 の夜）
- 同じ場面を 3 案。場面: 盤面の中心に恒星、周りに Tier 0〜6 の天体が 6 つ、うち 2 つが合体する瞬間。画面の上に時間と得点、下に次の天体 3 つ。スマホの縦（390×844）。
- 3 案の違いは、DESIGN.md の中で振る（例: 格子の細かさ 64 と 80、天体の点の並び方「密」と「輪」、中心の恒星の描き方）。DESIGN.md から外れた案は出さない。
- 作り方: 画像を作る道具が使えるならそれで。使えなければ HTML 1 枚（`dev/dots-board.html` など）で描いて撮る。どちらでも、最後は PNG にする。
- 置き場所: `docs/notes/D/design/2026-11-19_board_a.png`・`_b.png`・`_c.png`。各案に 1 行の説明（何を変えたか）を `docs/notes/D/design/README.md` に。
- push したら、進み具合の「リーダーへの依頼」に「見た目の案 3 つを置いた。持ち主に出してほしい」と書く。
- 自分で確かめる事（出す前に）: スマホの大きさで、一番小さい天体の形と Tier が見分けられるか。手本 3 つと並べて、似ている所と違う所を 3 行ずつ記録に書く。DESIGN.md 8 章の「使わない物」が入っていないか。

## 2. 題目 10 の続き（D）: 選ばれた案を本体に
- 持ち主が選んだら、`src/render/` の天体と盤面を点の格子で描き直す。描き方の芯（格子を作る・点を点ける・明るさの段）は 1 か所にまとめ、C の演出もそれを使えるようにする（`src/render/dots/` など）。
- 文字・結果画面・ボタン・切り替えも同じ言葉にする（DESIGN.md 6 章）。本体だけ直して端を残すと浮く。
- 見本ページ: `dev/dots.html`。幅 390・768・1440 で撮って、選ばれた案の絵と並べて直す。

## 3. 題目 11（C）: 点の動き（題目 000 を PR に出した後）
- D の描き方の芯を使って、合体・連鎖・超新星を点の動きで作り直す（DESIGN.md 3 章・7 章）。今の `src/effects/` の粒・輪・光は、合わなければ消す。
- 先に、動きの案を 3 つ、短い動画（各 3 秒）か動く HTML で出す。場面は「合体 1 回」「5 連鎖」「超新星」。置き場所 `docs/notes/C/design/`。持ち主が選んでから本体に。
- ブラックホール: 出し方は持ち主に確認中（案: 条件を満たすと中心の恒星がつぶれてブラックホールになる）。決まったらこの紙に足す。それまでは作らない。
- 動きの良し悪しは、AI の審査役では決めない。見本ページの URL を出して、人の目を待つ。

## 4. やらない事
- 部品・層・粒の数を増やして良くしようとする事。
- 選ばれる前に本体へ入れる事。
- 審査役の AI の「良い」を合格として扱う事。
