# 担当 B の手順書 — 盤面と照準

あなたが作るのは「プレイヤーが見る盤面」と「撃つ操作」です。ゲームの主役の部分で、見た目の印象はほぼここで決まります。

- 最初に `docs/RULES.md` を読む（ルールと操作の正）。
- 作る部品: `createBoardRenderer`（`src/render/index.ts`）、`drawBody`（`src/render/bodies.ts`）、`createPointerInput`（`src/input/index.ts`）
- 形の決まり: `src/contracts/app.ts` の「担当 B」の部分
- 確かめる場所: `npm run dev` → `http://localhost:5173/dev/board.html`（上のボタンで盤面を切り替えられる。「90 秒遊んだ後」などで、山ができた状態を出せる）
- いまある【仮実装】は、単色の丸と点線だけ。全部作り直してよい。
- 演出（粒子、輪、浮き文字、揺れ）と音は担当 C、HUD とメニューは担当 D。**盤面の Canvas に描くのは下の手順に書いた物だけ。**
- 色と線の考え方は `SPEC.md` 6.1 と AGENTS.md 6 章。

各手順の最後に、AGENTS.md「2. 作業の流れ」の 4 つ（チェック → progress 更新 → commit と push → Pull Request）を必ず行う。

## 手順 1: 背景、リング、核

- 背景のグラデーション、星 120 個（位置は固定の種から。動かさない）。
- 射出リング（`LAUNCH_RADIUS`）は控えめに。**限界リング（`LIMIT_RADIUS`）は、このゲームで一番大事な線**なので、いつでも見分けられるように描く。
- `curr.overLimit` が true の間、限界リングを `--danger` 色にして脈打たせる（「いま熱量が上がっている」が盤面だけで分かるように）。
- 核（`CORE_RADIUS`）と外側の光。熱量の状態（`src/shared/heat.ts` の `heatState`）で光の広さと脈動が変わる。熱量が今どのくらいかを、核のまわりの輪などで盤面の中にも示す（色は `HEAT_STATE_COLOR`）。
- `frame.dimmed` が true のときは盤面全体を暗くする。`frame.reducedMotion` が true のときは脈動を止める。
- 星など変わらない物は、毎フレーム描き直さずに別の Canvas へ 1 回描いて貼る。`resize` のたびに作り直す。

完了条件:
- [ ] 見本ページの「熱量 0 / 30 / 60 / 90」で、核の様子と熱量の表示が変わる
- [ ] 限界リングが、天体が積もった状態（「180 秒遊んだ後」）でもはっきり見える
- [ ] 「大きさ」を動かしても、ぼやけたり位置がずれたりしない（画素密度は `fitCanvas` に任せる）
- [ ] 全部同じ太さの線にしない。手本は古い天文機器や星図（AGENTS.md 6 章）

## 手順 2: 天体の描き分け

読む所: `SPEC.md` 4.2（描き方の例。半径の数値は古いので `TIER_RADIUS` を使う）

- `drawBody` を Tier 0〜8 の描き方に作り直す。**関数の名前と引数は変えない**（担当 C・D も使う）。
  - 引数の座標と半径は、呼び出し側の座標系のまま使う。HUD から小さく（半径 8〜30 くらいで）呼ばれても崩れないこと。
  - 模様の位置は `options.seed`（天体の ID）から決め、フレームごとに変わらないようにする。
  - 色だけでなく、輪郭と模様で見分けられること（Tier 5 と 6 は色が近い）。
  - 大きい天体は画面の大きな面積を占める（Tier 8 は直径 200）。大きく描いたときに見栄えがすること。
- 盤面では、`prev` と `curr` の位置を `alpha` で補間して描く。`prev` に無い天体（生まれたばかり）は `curr` の位置で描く。
- **半径は `BodyView.radius` を使う**（合体直後は、本来の大きさへ育つ途中の値が入っている）。
- `BodyView.overLimit` が true の天体は、縁を `--danger` 色で強調する（どの天体のせいで熱量が上がっているかを見せる）。
- 落ちている途中の天体にだけ、短い軌跡（`TRAIL_SECONDS`、`TRAIL_POINTS`）を付ける。止まった天体には付けない。`reducedMotion` のときは軌跡なし。

完了条件:
- [ ] 見本ページの「全 Tier」で、9 種類を文字なしで見分けられる
- [ ] 「180 秒遊んだ後」（40 体以上）で 60 fps を保つ（確認できなければ「未確認」と書く）
- [ ] `drawBody` を半径 10 で呼んでも形が分かる（見本ページに小さい一覧を足して確かめる）

## 手順 3: ポインター入力

読む所: `docs/RULES.md` の「操作」、`src/shared/launch.ts`

- `createPointerInput` を作り直す。Pointer Events で、マウスもタッチも同じ動き。
- 押した位置の角度が射出点（中心から `AIM_MIN_RADIUS` 未満の押下は無視）。
- 速度は必ず `aimVelocity(角度, ドラッグX, ドラッグY)` で求める。**ドラッグが短ければ「まっすぐ落とす」、長ければ「投げる」**になる。
- `setPointerCapture` で、指が盤面の外へ出ても続ける。
- 離したら `onLaunch(command)`。ドラッグなしで離した場合も呼ぶ（まっすぐ落とす）。無効な照準（`invalid`）で離したら何も呼ばない。
- **待ち時間中（`rejectReason === 'cooldown'`）は無効にしない。** 照準はでき、離したら `onLaunch` を呼ぶ（待ち時間が明けた瞬間に撃つ処理はアプリ側にある）。
- 取り消し: `cancel()` が呼ばれたとき、マウスの右ボタン、2 本目の指、`pointercancel`。取り消したら `onAim(null)` で、何も撃たない。
- 予測（`deps.predict`）を呼ぶのは、押したときとポインターが動いたときだけ、最大でも 33 ミリ秒に 1 回。
- `setEnabled(false)` の間は照準を始めない。進行中の照準は取り消す。
- 角度の計算など、純粋な計算は関数に分けてテストを書く（`src/input/*.test.ts`）。

完了条件:
- [ ] 見本ページで、押して離すとまっすぐ落ちる。引いて離すと、引いた向きへ飛ぶ
- [ ] 盤面の中心付近を押しても照準が始まらない
- [ ] 照準中に右クリックすると取り消され、何も撃たれない
- [ ] スマホ幅（開発者ツールの端末表示）で、ドラッグ中にページがスクロールしない

## 手順 4: 照準の表示

`frame.aim` が null でないときに描く。

- 射出リング上に、次の天体を半透明で（`aim.tier`、半径は `TIER_RADIUS`）。
- 道すじ（`aim.prediction.points`）を点線で。`frame.aimGuide` が false なら道すじは出さない（半透明の天体だけ出す）。
- 着く場所（道すじの最後の点）に、撃つ天体と同じ大きさの輪。
- `prediction.willMerge` が true なら、道すじと輪を `--cool` 色にし、当たる相手（`prediction.hitBodyId`）を軽く光らせる。**「ここに撃てば合体する」が一目で分かること。**
- 投げている（`aim.straight` が false）とき、強さが分かる表示（例: 半透明の天体のまわりの弧。`aim.speed` を `SPEED_MIN`〜`SPEED_MAX` の中の割合に）。
- `aim.invalid` が true のとき、半透明の天体と道すじを `--danger` 色に。

完了条件:
- [ ] 見本ページの「開始時」で真上を押すと、道すじと輪が合体の色になり、離すと合体する（右下の記録に merge と出る）
- [ ] 引いて投げると、道すじが曲がり、実際の飛び方と一致する
- [ ] 「予測線」のチェックを外すと道すじが消える

## 手順 5: 山が育ったときの見やすさ

- 「180 秒遊んだ後」の盤面で、限界リング、越えている天体、次に撃つ天体、道すじが、積もった天体に埋もれずに見えるか確かめ、描く順番と濃さを調整する。
- 合体で生まれた天体が育つ 0.12 秒が、不自然に見えないこと（急に大きくならない）。
- 熱量が「臨界」（75 以上）のとき、盤面を見ているだけで危ないと分かること。ただし天体が見えなくなる表現（全面を赤くする、強く揺らす）は不可。

完了条件:
- [ ] 見本ページで「180 秒遊んだ後」から自分で 1 分遊び、見づらい所がない
- [ ] 熱量 90 の盤面で、限界リングと越えた天体が最も目立つ

## 手順 6: 仕上げ

- 「動きを減らす」で、脈動・軌跡が止まる。
- 60 体の盤面で、1 フレームの描画が 4 ミリ秒以内を目安に（毎フレームの `new`、グラデーションの作り直しを避ける）。
- `npm run dev` の `/`（ゲーム本体）で 3 分遊び、コンソールにエラーが出ないこと。
- 見本ページに、確かめるのに便利なボタンを足してよい（`src/dev/board-demo.ts`）。
- progress に、目で確かめた項目と、確かめられなかった項目を分けて書く。
