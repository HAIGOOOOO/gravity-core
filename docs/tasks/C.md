# 担当 C の手順書 — 演出と音

あなたが作るのは「起きた事を気持ちよく伝える演出」と「効果音」です。融合がうれしいかどうかは、ほぼここで決まります。

- 作る部品: `createEffectsLayer`（`src/effects/index.ts`）、`createAudioManager`（`src/audio/index.ts`）
- 形の決まり: `src/contracts/app.ts` の「担当 C」の部分
- 確かめる場所: `npm run dev` → `http://localhost:5173/dev/effects.html`（ボタンで出来事を 1 つずつ起こせる。「自動プレイ」で実戦に近い頻度になる）
- いまある【仮実装】は、何も描かず何も鳴らさない。
- 演出は、**盤面の上に重ねた透明な Canvas**（`#effects`）に描く。盤面そのもの（天体、核、照準）は担当 B が別の Canvas に描くので、触らない。
- 天体の絵が必要なとき（融合で縮む 2 体など）は、担当 B の `drawBody`（`src/render/bodies.ts`）を import して使う。
- 座標は論理座標（中心が原点、一辺 960）。`src/shared/coords.ts` の `fitCanvas` と `applyLogicalTransform` を使う。

**方針: 思い切り派手に。** 控えめにまとめない（AGENTS.md 6 章）。ただし、軌道が見えなくなる演出（全画面の白飛び、長い停止）は不可。演出は見た目だけで、ゲームの進行を止めたり遅らせたりしない。

各手順の最後に、AGENTS.md「2. 作業の流れ」の 4 つ（チェック → progress 更新 → commit と push → Pull Request）を必ず行う。

## 手順 1: 演出の土台

読む所: SPEC.md 8.3、定数 `PARTICLE_CAP` `FLOAT_TEXT_CAP`

- 粒子、広がる輪、浮き文字の 3 種類を、あらかじめ確保した配列で使い回す（毎回 `new` しない）。
- 上限: 粒子 300、浮き文字 12。超える分は新しく出さない。
- `update(dt)` で進め、`draw()` で描く。`clear()` で全部消す。`resize(size)` は `fitCanvas`。
- 浮き文字は、1.2 秒かけて 24 上へ動きながら消える。文字の縁取りを付け、暗い盤面でも明るい天体の上でも読めるようにする。
- 寿命や減衰の計算は関数に分けてテストを書く（`src/effects/*.test.ts`）。

完了条件:
- [ ] 見本ページで、仮の粒子と輪と浮き文字が出て、消える
- [ ] 1 秒に 100 回出来事を起こしても、上限を超えず、動きが止まらない

## 手順 2: 出来事ごとの演出

読む所: SPEC.md 8.1（表の「見た目」と「長さ」の列）、6.5 の 10、6.8

`handleEvents(events, snapshot)` で受け取った出来事ごとに演出を出す。場所は `event.x`・`event.y`。

| 出来事 | 作る物 |
|---|---|
| `launch` | 射出点の輪 |
| `bounce` | 白い火花 4 個。`tooFast` なら `--warn` 色で 8 個 |
| `merge` | 元の 2 体が接点へ縮む → 新しい天体が白く光りながら現れる → 輪が広がる → 粒子（8 ＋ 2 × Tier 個）→ 得点の浮き文字（「＋330」）。`chain` が 2 以上なら輪を `--chain` 色にし、「連鎖 ×3」を大きく出す |
| `absorb` | 天体から核へ吸い込まれる線、核の閃光、核の横に「＋9 核へ落下」 |
| `escape` | 外縁の短い弧、その内側に「＋4 軌道から流出」（文字は盤面の中に収める） |
| `densityPurge` | 天体が `--danger` 色の輪になって消える、「＋8 過密」 |
| `supernova` | 2 体が縮む → 二重の輪が半径 300 まで → 粒子 40 個 →「超新星反応 ＋45,000」。この演出がゲームで一番大きい |

- 熱量の文字は、増えるときは `--danger`、減るとき（融合の「−3」）は `--cool`。数値は `event.heatDelta`、得点は `event.scoreDelta` を使う（自分で計算しない）。
- 色は、その Tier の `TIER_COLOR`。Tier が上がるほど大きく、長く、派手に。
- 融合で縮む 2 体の絵は、`event.sourceTier` と `drawBody` で描く（位置は `event.x`・`event.y` の周り。元の正確な位置は分からなくてよい）。

完了条件:
- [ ] 見本ページのボタンで、7 種類の出来事を見た目だけで区別できる
- [ ] Tier のスライダーを 0 → 7 に上げると、融合の演出がはっきり大きくなる
- [ ] 連鎖のスライダーを上げると、連鎖の表示が出て、色が変わる
- [ ] 「自動プレイ（混雑）」を 1 分見て、演出で天体や軌道が隠れ続けない

## 手順 3: 揺れ、終了演出、「動きを減らす」

読む所: SPEC.md 8.1（融合 Tier 4 以上・超新星・終了の行）、8.5

- 揺れ: `createEffectsLayer` の第 2 引数 `shakeTarget` に、CSS の `transform: translate(...)` を付けて揺らす。Tier 4 以上の融合で 2px、Tier 6 以上で 4px、超新星で 6px、0.1 秒。終わったら必ず元に戻す。
- `playGameOver()`: 0.55 秒の終了演出。盤面全体が薄くなり、核の光が半径 120 まで `--danger` 色で広がる。
- `setReducedMotion(true)` のとき: 揺れなし、粒子なし、広がる輪は「動かない輪を 0.3 秒表示」に、終了演出は省く。浮き文字は出す（情報なので）。

完了条件:
- [ ] 「動きを減らす」を入れても、何が起きたかが文字と静止した輪で分かる
- [ ] 揺れの後、盤面の位置が元に戻っている（連打しても、ずれが残らない）

## 手順 4: 音の土台と、出来事の音

読む所: SPEC.md 8.4、8.1（「音」の列）、8.3

- Web Audio API で、その場で合成する。**音声ファイルを足さない。**
- `unlock()` で `AudioContext` を作る（ユーザーの操作の中で呼ばれる）。それより前に `handleEvents` が来ても、エラーにせず何も鳴らさない。
- つなぎ方: 発振器 → 音量の山（0.005 秒で立ち上がり、指定の長さで減衰）→ 全体音量 → コンプレッサー → 出力。
- 全体音量は「設定の音量 ÷ 100 × 0.8」。`sfx` が false なら何も鳴らさない。
- 同時に 12 音まで。反発音は 0.25 秒あたり 4 回まで。
- 出来事ごとの音は SPEC.md 8.1 の表のとおり。融合の基音は `523 × 2^(−Tier ÷ 6)` Hz。連鎖は 1 オクターブ上の正弦波を重ね、連鎖 1 ごとに全音 1 つ高く。
- 音の高さや長さの計算は関数に分けてテストを書く（`src/audio/*.test.ts`。Web Audio 自体はテストしなくてよい）。
- **鳴り始めは小さく。** 耳に刺さる音にしない。10 分聞いても疲れない音量と音色にする。

完了条件:
- [ ] 見本ページで「音を有効にする」を押した後、各ボタンで違う音が鳴る
- [ ] Tier を上げると融合音が低く長くなる。連鎖を上げると高い音が重なる
- [ ] 「効果音」を切ると何も鳴らない。音量のスライダーが効く
- [ ] 「自動プレイ（混雑）」で、反発音が鳴りっぱなしにならない

## 手順 5: 残りの音

読む所: SPEC.md 8.1（熱量 90 以上・終了・ベスト更新・ボタンの行）

- `setCritical(true)` の間、70 Hz の低い音を 1 秒おきに鳴らす。false で止める。
- `gameOver` の出来事で終了音。`play('bestScore')`、`play('button')`。
- `suspend()` で音を止め（一時停止）、`resume()` で戻す。臨界の警告音も一緒に止まること。

完了条件:
