# 担当 C の題目 — 「感じる」の全部

> **2026-10-16: 音の作業は中止（持ち主とリーダーが持つ）。題目 1・2・3 と、各題目の音の部分はやらない。題目 4 → 5 → 6 → 7 の見た目の部分から進める。この手順書は近いうちに作り直す。**

あなたが持つのは、遊ぶ人の**体に届く物の全部**です。合体の瞬間の演出、効果音、プレイで変わっていく曲、着地の重さ、危なさの伝わり方、負けた瞬間。前は「演出と音」を一通り付ける所まででしたが、ここからは 1 つずつ、売り物の水準まで仕上げます。

いまの物は、出来事ごとに光と音が出ます。しかし、どの合体も同じ形の輪と火花で、音は発振器の単音です。**9 種の合体を 9 回見ても、同じ物を 9 回見た感じ**がします。ここを作り替えます。

- 進め方は `AGENTS.md` の 1.5 章（周回）と 1.6 章（審査役）。**1 つの題目を最低 3 周。合否を出すのはリーダーだけ。**
- 作る部品の形: `src/contracts/app.ts` の `createEffectsLayer`、`createAudioManager`
- 見本ページ: `dev/effects.html`、自分で作る `dev/sound.html`
- 天体の絵は担当 D の `drawBody` を使う。担当 D が絵を作り替えている途中なので、絵が変わっても合うように作る。
- 演出は見た目と音だけ。ゲームの進行を止めたり遅らせたりしない（進行に手を入れたい時は、リーダーへの依頼に書く。合体の「一瞬の間」などは、リーダーが芯の側で用意します）。
- 天体と限界リングが見えなくなる演出（全画面の白飛びなど）は不可。それ以外は、**控えめにまとめない**。
- 好みの正解は、この手順書に書いてありません。**あなたが調べ、案を出し、理由を持って選びます。**

## 音を「耳なしで」確かめる方法（全題目で使う）

あなたも、自動の動画も、音を聞けません。だから、音は必ず数字と画像にしてから審査役に渡します。`src/audio/verify.ts` に `OfflineAudioContext` で音を作って測る仕組みがあります。これを育てて、`dev/sound.html` で次を出せるようにします。

- 波形の画像と、スペクトログラム（横が時間、縦が高さ、明るさが強さ）の画像
- 最大の音量（1.0 を超えない。目安は 0.9 以下）、平均の音量（RMS）、音が割れた回数（0 であること）
- 鳴り始めの速さ（0 から最大の 9 割までの時間）、消えるまでの時間
- 低い・中くらい・高い、の 3 つの帯の強さの割合
- 2 つの音の聞き分け: スペクトログラムを並べて、違いが目で分かるか

審査役には、この画像と数字を渡し、「この音は何が起きた音に聞こえそうか」「ほかの音と区別できそうか」「耳に痛そうな所はどこか」を答えさせます。**それでも、耳で確かめた事にはなりません。記録の「確かめていない事」に必ず書く。**

## 題目 1: 音の方向を決める

- **調べる**: 物が当たる、くっつく、育つ、限界に近づく、を音で表している実在の作品・楽器・道具・自然の音を 10 個以上調べ、何が効いているのかを書く。
- **案を 3 つ**: 向きの違う 3 案（たとえば、合成した音だけ／録音された本物の音を元にする／楽器の音階で組む、など。これは例で、答えではない）。各案で同じ 6 つの場面（落とす、当たる、小さい合体、大きい合体、限界を越えた、終了）を作り、`dev/sound.html` で聞き比べられるようにする。画像と数字も並べる。
- 素材を足してよい（`public/audio/`、`CREDITS.md` 必須、合計 12 MB まで）。
- 自分のおすすめを 1 つ決め、理由を書く。

測る基準:
- [ ] 3 案のスペクトログラムを見て、案を取り違えないくらい違う
- [ ] どの音も最大の音量 0.9 以下、割れ 0 回
- [ ] 鳴り始めが、耳に刺さらない速さになっている（3ms 以上かけて立ち上がる）

提出したら、返事を待たずに、自分のおすすめの案で進む。

## 題目 2: 効果音一式

題目 1 の方向で、全部の音を作ります。**1 周で 1 種類**。

- 落とす、当たる、合体、超新星、限界を越えた・戻った、熱量の状態が変わった、終了、画面の操作音（押す、開く、閉じる、選ぶ）。
- **当たる音**は、ぶつかった速さ（`impactSpeed`）と天体の大きさで変わる。同じ音を音量だけ変えて使い回さない。
- **合体の音**は、9 種で別の音にする。大きい天体ほど、低く、長く、重く。**連鎖**が続くほど、音が上がっていき、次を鳴らしたくなること。
- 短い時間に同じ音が重なっても、うるさくならない（数を絞る、少しずつ変える）。同じ音を 2 回続けて鳴らした時、まったく同じ波形にしない。
- 音を切る設定、音量の設定に従う。

測る基準:
- [ ] 9 種の合体のスペクトログラムを混ぜて、Tier の順に並べ直せる（審査役に試させる）
- [ ] 1 秒に 30 回の出来事を起こしても、最大の音量 0.9 以下、割れ 0 回
- [ ] 出来事が起きてから音が出るまで 20ms 以内

## 題目 3: プレイで変わる曲

曲を流すだけにしない。**いまの盤面の状態が、曲に出る。**

- 山が育つほど、音の層が増える。熱量が上がるほど、緊張が増す。連鎖の間は、曲がそれに乗る。限界を越えている間は、はっきり変わる。終了で、崩れる。
- 層の出入りは、拍の区切りに合わせる。ぶつ切りにしない。
- 合体の音が、曲の音階と拍に合う（題目 2 の音を、ここで調整し直してよい）。
- 曲の作り方は自由（その場で合成する、短い素材を重ねる、など）。素材を使うなら `CREDITS.md`。持ち主やチームの人が作った曲は入れない。
- 3 分聞き続けても、同じ 4 小節の繰り返しに聞こえないこと。
- 曲を切る設定を足したい時は、担当 D とリーダーへの依頼に書く。

測る基準:
- [ ] 自動プレイ 3 分の録音（`OfflineAudioContext`）のスペクトログラムで、序盤・中盤・終盤が見分けられる
- [ ] 熱量 0 と 80 の 10 秒ずつを並べて、違いが画像で分かる
- [ ] 曲と効果音を同時に鳴らして、最大の音量 0.9 以下、割れ 0 回
- [ ] 曲の処理を入れても、ゲーム本体が 1 秒 60 コマを保つ

## 題目 4: 合体の演出を、9 種それぞれ別物にする

**1 周で 1 種**。Tier 0 から順に。

- いまは、同じ輪と火花が大きくなるだけです。9 種で、**何が起きているのか**を変える（何が飛び、何が残り、どう消えるか）。天体の種類（`TIER_NAMES`）から考える。
- 合体は「2 つが消えて 1 つが出る」のではなく、**2 つが 1 つになる**ように見せる。生まれた天体が育つ 0.12 秒（`GROW_SECONDS`）と合わせる。
- 小さい合体は 1 回のプレイで何十回も起きます。**50 回見ても飽きず、邪魔にならない**こと。大きい合体は数回しか起きません。**起きたら手が止まる**くらいの物にする。
- 得点の出し方も、ここで作り直す。
- 動きを減らす設定の時の、別の見せ方を用意する（消すだけにしない）。

測る基準（1 種ごと）:
- [ ] 0.05 秒ごとのスクリーンショットを並べて、ほかの 8 種と取り違えない
- [ ] 演出の最中も、まわりの天体と限界リングが見える
- [ ] その合体を 1 秒に 10 回起こしても、1 コマ 16.7ms 以内

## 題目 5: 連鎖と超新星

- **連鎖**: 2 連鎖、3 連鎖、…と、段が上がるたびに、前より上の事が起きる。最大（倍率 3.0）に届いた時は、特別にする。連鎖が切れた事も、静かに伝える。
- **超新星**: 1 回のプレイで 1 度あるかどうかの出来事です。このゲームで一番の見せ場にする。数秒かけてよい。ただし、進行は止めず、盤面は見えたままにする。
- どちらも、音（題目 2）と曲（題目 3）と合わせて 1 つの出来事にする。

測る基準:
- [ ] 連鎖 1〜5 のスクリーンショットを混ぜて、順番に並べ直せる
- [ ] 超新星の最中の、0.25 秒ごとのどの絵にも、天体と限界リングが写っている
- [ ] 超新星の最中も 1 コマ 16.7ms 以内（重いなら、軽い設定を用意し、両方の重さを書く）

## 題目 6: 危なさと、負けた瞬間

- 限界を越えた瞬間、越え続けている間、戻った瞬間。熱量が 25・50・75 を越えた瞬間。数字を見ていなくても、体で分かること（盤面そのものの変化は担当 D。あなたは、その上に重ねる動き・揺れ・音）。
- 危ない時ほど騒がしくして、操作の邪魔をしない。**危ない時ほど、狙いやすく**なっていること。
- **負けた瞬間**は、悔しさと「もう 1 回」が残るように。何が原因だったかが、演出で分かる。
- 揺れは、終わったら必ず元の位置に戻る。酔わない強さにする。

測る基準:
- [ ] 熱量 20 / 45 / 70 / 95 の 3 秒ずつの動画を、音なしで見て、危ない順に並べ直せる
- [ ] 揺れの最大は盤面の幅の 1.5% 以内、終わってから 0.3 秒以内にずれ 0
- [ ] 動きを減らす設定で、揺れ 0

## 題目 7: 手触り

着地、押しのけ、止まる、の小さい出来事。派手ではないが、1 回のプレイで何百回も起きます。

- 落とした天体が当たった時の、重さの差（小さい物は軽く、大きい物は重く）。
- 目に見える反応と音が、ずれない。
- 何も起きていない時の盤面にも、生きている感じがある（やりすぎない）。

測る基準:
- [ ] 当たってから見た目の反応まで 1 コマ以内、音まで 20ms 以内
- [ ] Tier 0 と Tier 6 の着地を並べた動画で、重さの差が分かる（審査役に、どちらが重いか当てさせる）

## 題目 8: 重さの管理

- 全部の演出を入れた状態で、自動プレイ 3 分の、1 コマの時間の平均と最悪を測る。
- 重い設定・普通の設定・軽い設定を用意し、それぞれの重さを書く。既定は「普通」で 1 秒 60 コマ。
- 長く遊んでも、だんだん重くならない（10 分後に、使っている粒の数やメモリが増え続けていない）。

測る基準:
- [ ] 普通の設定で、自動プレイ 3 分の最悪の 1 コマが 16.7ms 以内
- [ ] 10 分後の粒の数と、音の同時発音数が、1 分後と同じ範囲
