# 担当 D の手順書 — 画面・保存・ランキング

あなたが作るのは「盤面以外の全部の画面」と「記録の保存」と「ランキングページ」です。最初に見えるタイトルも、負けた理由を見せる結果画面も、ここです。

- 作る部品: `createLayout(root, onResize)` `createHud(root, onIntent)` `createOverlays(root, onIntent)`（`src/ui/index.ts`）、`createSaveStore` `createRankingStore`（`src/storage/index.ts`）、ランキングページ（`ranking.html` `src/ranking.ts`）
- 形の決まり: `src/contracts/app.ts` の「担当 D」の部分
- 確かめる場所: `npm run dev` → `http://localhost:5173/dev/screens.html`（上のボタンで各画面を出せる。押したボタンの意図は右下に出るだけで、画面は切り替わらない）
- いまある【仮実装】は、文字 1 行の HUD と、ボタンだけのカード。全部作り直してよい。ファイルは分けてよい（`hud.ts` `overlays.ts` `layout.ts` など）。
- **画面は意図（`UiIntent`）を伝えるだけ。** 状態を切り替えるのはアプリ（リーダー担当）。ボタンを押したら `onIntent(...)` を呼び、アプリが `overlays.show(...)` を呼び返すのを待つ。例外は「遊び方」と「設定」で、これは自分で開いて、閉じたら直前の画面に戻してよい。
- `index.html` の骨組み（`#app` `#board-wrap` `#hud` `#overlay-root`）は変えられない。その中身を JavaScript と CSS で作る。
- `src/styles/game.css` の「変えない」と書かれた部分（2 枚の Canvas を重ねる所）は残す。
- 天体の絵（次の天体、ランキングの最高 Tier）は、担当 B の `drawBody`（`src/render/bodies.ts`）を小さな Canvas に描いて使う。
- `src/ui/strings.ts` に既にあるキーは、アプリが使っているので名前を変えない・消さない。足すのは自由。

各手順の最後に、AGENTS.md「2. 作業の流れ」の 4 つ（チェック → progress 更新 → commit と push → Pull Request）を必ず行う。

## 手順 1: レイアウト

読む所: SPEC.md 6.1、6.2（表と図の説明）、6.3、6.4

- `createLayout(root, onResize)`: 画面サイズから盤面の一辺 S を決め、`--board-size` を設定し、変わるたびに `onResize(S)` を呼ぶ。
  - PC（幅 900px 以上かつ横長）: `S = min(高さ − 48, 幅 − 280 − 72)`。盤面の右に幅 280px のパネル。
  - スマホ縦: `S = min(幅 − 16, 高さ − 56 − 88 − 安全領域)`。上に 56px、下に 88px の帯。
  - スマホ横（高さ 500px 未満）: `S = 高さ − 16`。パネル幅 200px。
- S を決める計算は、DOM を使わない関数に分けてテストを書く（`src/ui/layout.test.ts`。入力は幅・高さ・安全領域、出力は S と配置の種類）。
- スクロールさせない。足りないときは盤面を縮める。最小は 240px。
- `#hud` の中に、PC ではパネル、スマホ縦では上下の帯を作る（CSS のグリッドで配置を切り替える）。

完了条件:
- [ ] 1280×720、900×600、360×640、640×360 の 4 つで、盤面・情報・ボタンが重ならず、切れない（開発者ツールの端末表示で確認）
- [ ] 画面サイズを変えると、右下の記録に新しい「盤面の一辺」が出る

## 手順 2: HUD

読む所: SPEC.md 6.3、6.4、5.1、6.9

- スコア（3 桁区切り、0.3 秒かけて数え上がる）とベスト。
- 核熱量: 横棒、「70 / 100」（小数は切り捨て）、状態名。色と名前は `src/shared/heat.ts`。**色だけに頼らない**（数値と状態名を必ず出す）。`aria-live="polite"`。
- 次の天体 3 個: 先頭は大きく（PC 64px、スマホ 48px）、残りは小さく。`drawBody` で描く。先頭が変わったときだけ描き直す。
- 連鎖: `showChain(chain)` で「連鎖 ×3（2.0 倍）」を `--chain` 色で 2 秒。倍率は `chainLabel`（strings.ts）と、`min(3, 1 + 0.5 × (連鎖 − 1))` で求める。
- ヒント（トースト）: `showToast(text, seconds)`。盤面の下側中央に 1 行。同時に 1 つ。
- ボタン: 一時停止（`{ kind: 'pause' }`）、音の入切（`{ kind: 'toggleSfx' }`、`setSfxOn` で絵を切り替える）、ランキング（PC のみ。`{ kind: 'openRanking' }`）。アイコンだけのボタンには `aria-label`。意図は `createHud(root, onIntent)` の第 2 引数で伝える。
- `update` は毎フレーム呼ばれる。値が変わっていない部分の DOM は書き換えない。

- [ ] 次の天体が、盤面と同じ絵で出る

## 手順 3: 重ねて出す画面

読む所: SPEC.md 6.6（表の全部）、6.8、6.9、9.1、9.2

`createOverlays(root, onIntent)` の `show(screen, data)` で 5 種類を出す。`show(null, ...)` で閉じる。

- タイトル: ロゴ、説明文、ベスト、「はじめる」（主ボタン）「遊び方」「ランキング」「設定」。**最初の印象なので、ここは特に丁寧に。** ただのカードにボタンを並べただけにしない。
- 遊び方: 絵と 1 文のカード 3 枚、「閉じる」。絵は Canvas か SVG で描く（画像ファイルを足さない）。
- 設定: 効果音、音量（0〜100）、動きを減らす（入・切・端末に合わせる）、時刻マーカー、名前（12 文字まで）、「記録を消す」（確認あり）、「閉じる」。変更のたびに `{ kind: 'settingsChanged', settings }`。名前は `{ kind: 'rename', name }`。
- 一時停止: 「つづける」（主）「最初から」（確認あり）「設定」「タイトルへ」（確認あり）。確認の文言は `STRINGS.confirmDiscard`。
- 結果: 「核が限界に達した」、スコア（48px）、「ベスト更新！」、順位（`result.rank` が null でなければ「この端末で 3 位」）、最高 Tier（絵と名前）・最大連鎖・プレイ時間（分:秒）・射出数・融合数、**「熱量が増えた理由」**（核へ落下・流出・過密の 3 色の横棒と数値）、名前の入力欄、「もう一度」（主）「ランキングを見る」「結果をコピー」「タイトルへ」。
- 開いたとき、主ボタンにフォーカスを置く。Tab でボタンを順に回れる。開いている間、フォーカスが後ろの画面へ出ない。フォーカスの枠は `--cool` の 2px。
- `show` が同じ画面で呼び直されることがある（順位が後から届く）。そのとき入力中の名前やフォーカスを失わないこと。
- 確認ダイアログは `window.confirm` を使わず、カードの中に出す。

完了条件:

- [ ] キーボードだけ（Tab、Enter、Space）で全部のボタンを押せる
- [ ] 幅 360px でも、結果の内容が全部見える（カードの中だけスクロールしてよい）

## 手順 4: 保存

読む所: SPEC.md 10.1、10.2、10.3

- `createSaveStore()`: `localStorage` のキー `gravity-core:v1`。
  - `load()` は必ず使える値を返す。無い・壊れている・版が違う・項目が欠けている場合は、元の文字列を `gravity-core:backup` に退避して、初期値（欠けた項目だけ初期値で補うのでもよい）を返す。
  - `save()` は、保存が拒否されても例外を投げない。その場合はメモリ上の値で動き続ける。
  - `localStorage` に触るのは `src/storage/` の中だけ。
- `createRankingStore(save)`: 追加したらスコア順（同点は日時が早い順）に並べ、11 件目以降を捨てる。`bestScore` と `lastRecordId` も更新する。`submit` の戻り値は順位（10 位以内でなければ null）。
- 名前は前後の空白を除き、12 文字で切る。空なら「PLAYER」。
- テスト（`src/storage/*.test.ts`）: 壊れた文字列、版が違う、項目が欠けた、11 件目、同点、保存が例外を投げる、の各場合。`localStorage` は自作の偽物（`getItem` `setItem` を持つオブジェクト）を引数で差し替えられるようにする。

完了条件:
- [ ] 見本ページで「見本の記録を 10 件入れる」→ ページを読み直しても記録が残る
- [ ] 開発者ツールで `gravity-core:v1` を壊れた文字列に書き換えて読み直しても、ゲームが始まる
- [ ] テストが上の 6 つの場合を網羅している
