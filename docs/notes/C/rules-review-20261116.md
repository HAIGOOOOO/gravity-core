# 題目000・1周目の初見審査と修正

独立した初見役がアプリ内ブラウザー390×844で、連鎖の一投と見返し、崩壊の解放から発動、成長、連投、敗因、自由プレイを操作した。実機タッチ・実聴はなし。比較対象は『スイカゲーム』。次の物、落下位置、結果を盤面の視線のまま追える点を参考にした。

| 重さ | 見つかった問題 | 今回の対応 |
|---|---|---|
| ★ | 見返しで合体ごとの冷却量が読めず、停止の案内まで限界外の赤になる | 盤面下にこの合体の冷却と同じ刻みの熱変化を表示。再生の案内は中立色 |
| ★ | 崩壊の力をためた後、一投する盤面が画面外に残る | 準備・射出と崩壊を盤面下へ。満タンの投入位置に金の輪を表示。画面上端で盤面が切れていれば戻す |
| ★ | 成長結果の凡例と結論が再生操作より下にあり、盤面と一緒に見られない | 盤面直下に予告と結果の内外、線の短い凡例 |
| 4 | 崩壊を待っている間に方角を選ぶよう案内される | 崩壊を押すと再開する案内に変更 |
| 5 | 合体のない結果でも「合体の瞬間へ戻せます」と出る | その記録にある操作だけを表示 |
| 6 | 崩壊後の冷却結果の前に衛星の図が残る | 結果では準備図を畳む |
| 7 | 3投目だけ比べるために前の2投もやり直す | 2投後の盤面を復元する「3投目をもう一度」 |
| 8 | 真上への案内が3箇所に重なる | 投げ方は盤面の金の輪にそろえる |
| 9 | 通常幅で熱と次の天体が重複する | 熱とメーターは盤面下、次の天体は各幅で1箇所 |
| 10 | 補助や計測まで同じ枠と色で、主操作が埋もれる | 崩壊の準備は盤面下と金色の枠で区別。他の練習の視覚的な順位は再審査 |

初見役が機械的に感じた点は同文反復、定型的な長文、同形のボタン、色の意味混在、情報の重複。別の審査役による修正後の確認はこれから。

親が390×844で確認。見返し第1合体は熱68.0→66.2（冷却−2.0、限界外＋0.2）・100点、第2合体は67.3→62.5（冷却−5.0、限界外＋0.2）・430点。成長は静止時の予告が限界外で、実際は限界内。盤面上端と凡例下端が各115・607px。崩壊の満タン時、補正後の盤面上端12px、ボタン下端483px。盤面の輪から直接一投し、崩壊−18.6、結果0.0。連投は右右右の最後＋2から2投後へ戻り、左で＋0。画像は [合体の熱](rules-contact-heat-20261116.png) と [崩壊の一投](rules-collapse-aim-20261116.png)。

本線の共有更新も統合。現行の指紋を持つ形式4で崩壊を保持し、旧Cの実物コードと端末保存を復元した。旧Cのコードは同じルールのとき3,310点を再現。本線の旧コードは入力を読めるが、異なるルールとして再生を止める。元の33投を現行ルールで再計算した10分の見本は [共有画面](share-sample-20261116.png) で7,630点を確認した。

## 修正後の品質審査

別の品質役が1280×720と390×844で6項目を実操作。連鎖の外し、崩壊の発動と期限切れ、3投目の再試行、敗因の左右比較、自由プレイの盤面入力を含む。実聴と実機タッチはなし。

| 重さ | 追加の指摘 | 対応 |
|---|---|---|
| ★ | 通常幅の成長は結論と凡例が画面外 | 盤面寸法の計算で凡例分を確保。1280×720でスクロール0、凡例下端698px |
| ★ | 連投の右と左で、結果の収支の起点が40.0と26.0に変わる | どちらも3投目の直前から表示。実操作で26.0→27.9と26.0→25.9 |
| ★ | 崩壊は満タンで補助を外すと準備をやり直し。期限切れの再試行も0/12に戻る | 補助は次の一投に適用。満タンの配置を保存し、一投から再試行。390幅で期限切れ前後が12/12と確認 |
| 4 | 自由プレイの盤面はキーボードで射出できない | フォーカス、←／→、スペースまたはEnter。アプリ内ブラウザーでキーだけで射出を確認 |
| 5 | スマホの自由プレイに得点と連鎖が出ない | 熱のそばに得点と最大連鎖を表示 |
| 6 | 崩壊の見返しは準備から始まる | 「崩壊の発動から見る」で直前へ移動し、1/4速と発動中の熱を表示。実操作と試験で確認 |
| 7 | 3投目だけやり直すと0.01秒の見返しが出る | 3投目だけの結果では熱の比較を残し、短い見返しを省く |
| 8 | スマホで見返しに切り替えると盤面の縦位置が動く | 残り。通常の画面位置の保持を確認する |
| 9 | 崩壊の一投の指示が2箇所にある | 残り。補助と受付の説明に絞る |
| 10 | 限界外の原因が3箇所で似た言い方になる | 残り。原因の天体と次の操作の近くに集める |

比較対象は『スイカゲーム』。盤面の周囲で入力・次の物・得点を追える点を参考にした。同じ状態の言い換え、結果を問わない定型の説明、操作の優先度の違いが目立たない枠、短い再生に残る共通表示、比較の意味が弱くなる数値配置を機械的に見える点とした。

## 継続する密集盤面の計測

開発用の「密集盤面で180コマ」は通常開始から実際に約93秒自動プレイした盤面を作り、同じ投げ方を続けて測る。アプリ内ブラウザー1280×720、音なし、両方とも46〜50体で180コマ進行、ゲーム内経過2.99秒。最初の計測は準備中に発番された表示時刻からの空白が混ざったため、準備完了後のコマから集計し直した。

| 演出 | 更新＋描画JSの95%点 / 最大 | 描画JSの95%点 | 表示間隔の中央値 / 95%点 / 最大 |
|---|---:|---:|---:|
| なし | 1.90 / 2.80ms | 1.30ms | 16.7 / 16.9 / 17.1ms |
| あり | 1.50 / 2.00ms | 1.00ms | 16.7 / 16.8 / 17.0ms |

[演出ありの結果](rules-dense-20261116.png)。同一環境の各1回、約3秒のデモ測定。演出を有効にすると速くなるという結論には使わない。最大表示間隔は16.7msを少し超え、実機や本体の3分計測は残る。

この場面の187投を共有すると、同じコードでNodeの結果242,150点、アプリ内ブラウザーの結果253,590点になった。長い共有の計算差は調査中。
