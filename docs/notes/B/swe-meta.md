# swe-meta — 日替わりの盤面と図鑑（meta）

## いま
- できた物: `src/meta/` に storage（保存の口＋安全な JSON）、daily（JST 日付→シード・本番/練習・履歴・連続日数・履歴の上限）、codex（表駆動 34 項目・発見時刻/プレイ番号/tick・観測時刻つき）、unlocks（12 件＋文脈の組み立て＋解放の差分）とテスト 3 本。
- この回: 前回の検査失敗 2 件を修正（`-1` ms の JST 日付を UTC 基準で期待していた誤り→正しい値 `1970-01-01` へ、`Set` に `arrayContaining` を当てていた誤り→配列化）。あわせて日付まわりを強化: `jstDateKey` は年を 4 桁ゼロ詰めし Date 範囲外・西暦 0 未満・1 万年以降は既定日付へ落とす（出力が必ず `dayNumberOf` を通る形）、`dayNumberOf` は西暦 3 桁以下の年も正しく検証。往復・履歴の並び順・全項目の必須フィールド・全解放のテストを追加。
- 次: 台本の検査結果を見て直す → 解放ペースを 200 プレイ規模で測る → 初見の人が hint で「次に何を狙うか」言えるか項目ごとに点検。

## 決めたことと理由
- シード: 日付キー → 日数 → 全単射の mix32。奇数の掛け算と XOR シフトは逆写像を持つので合成も全単射。「365 日で重なりなし」が確率ではなく構造で保証される。
- 練習は本番と別系列のシード: 同じ盤面で練習できると本番の先読みができてしまうため。呼ぶたび盤面が変わる。
- ランは開始時の日付に結びつける（`DailyRun` が dateKey を持つ）: 0 時またぎで遊んでも、記録は開始日へ行き壊れない。
- 図鑑は表駆動: 項目は `CODEX_ENTRIES` にだけ書き、各行が `found(ctx)` を持つ。エンジンは表をなめるだけ。種類を足す＝表に 1 行足す。
- 未発見の項目は名前を「？？？」で隠し hint を出す（「次に何を狙うか」を言えるように）。天体は Tier 番号で手がかりを書く。
- 発見記録は `foundAtMs`（実時刻）・`runIndex`・`tick`・`recordId?`。再生へ飛べる形。時刻は呼び出し側が渡すので純粋。
- unlocks も表駆動。条件は `UnlockContext`（図鑑数・回数・最高得点・本番日数）だけを見る純粋関数で、プレイ中にも確かめられる。遊びの芯は開放済みにする方針なので、解放は「続ける」側の機能だけ。
- `unlockContextFrom` で「図鑑の発見数 = `codex.progress().found`」「本番日数 = `daily.history()` の件数」の取り方を 1 か所に固定した。アプリ側は runs と bestScore だけ渡せばよい。
- 解放の通知は `newlyUnlocked(before, after)`（前の状態と今の状態の差分）で取る設計。ストア側に「解放済み」を持たせず、毎回文脈から純粋に評価するので矛盾しない。
- 図鑑の文脈に `nowMs`（観測時刻）を足し、実時刻で判定する項目（深夜の天文台）を 1 つ入れた。時刻は feed の meta から来るので純粋さは保つ。`JST_OFFSET_MS` は daily から export して共用（JST の定義を 2 か所に書かない）。
- 追加した項目: 大混雑（30 体同時）、沈黙の運行（60 秒無合体で生存）、深夜の天文台（JST 0〜5 時に観測）。表に 3 行足すだけで保存・一覧・判定が全部動く。
- `jstDateKey` の出力は「必ず `dayNumberOf` を通る形」に揃えた（年 4 桁ゼロ詰め＋範囲外は `1970-01-01`）。これで「時刻→キー→日数」の往復が任意の入力で壊れない。
- `dayNumberOf` は `Date.UTC(2000, m-1, d)` で日付を作ってから `setUTCFullYear(y)` で目的の年へ移す。Date.UTC が年 0〜99 を 1900 年代と解釈するのを避けられ、かつ丸め判定（2/30 等）は目的の年の暦で行える（`'2000-02-29'` は通り `'2026-02-29'` は捨てる）。

## ずるの余地（日替わり勝負）
- 端末の時計をずらせば未来/過去の本番を先取り・やり直しできる。サーバーが無いので完全には防げない。記録は端末内の自己申告として扱う。
- localStorage を消す・直せば履歴も消せる。本番の「1 日 1 回」はローカルの整合性の範囲で担保する。
- 対抗策を入れるなら: 未来日の記録を疑う、記録に直前の日付の連鎖署名を持たせる、など。必要になったら検討する。

## リーダーへの依頼
- 図鑑・解放の表示名と説明文を `src/ui/strings.ts`（担当 D）へ移してほしい。いまは `src/meta/codex.ts`・`unlocks.ts` の表の中に定数として同居している。
- `runIndex`（何回目のプレイか）と `recordId`（再生への ID）は呼び出し側が渡す形にした。アプリ側で記録数・記録 ID から供給してほしい。
- `daily-history` の解放は「本番 2 日ぶん」。`history()` から `officialDays` を数えて `UnlockContext` へ渡す想定。
