# 共有コードと再生（題目6、1周目）

## 実物を見て決めたこと

| 作品 | 操作や制約 | この見本で使う判断 |
|---|---|---|
| スプラトゥーン3 | 対戦をコードで共有し、メモリープレーヤーで見る。更新によって過去の記録を開けなくなることがある。 [任天堂の紹介](https://splatoon.nintendo.com/en/news/squid-research-lab-dives-deep-into-the-splatlands/) | 受け取る操作を貼り付けから始める。別版のコードには送り手と版を合わせるよう案内する。 |
| Trackmania | リーダーボード上の記録を選び、ゴーストを観戦できる。PCではリプレイファイルも開ける。 [公式ドキュメント](https://doc.trackmania.com/play/watch-replays/) | 確認した記録の概要から、その記録の再生を直接開く。 |
| Factorio | セーブに操作を持ち、最初から再現する。古い版やmodが異なると再生できない。 [公式Wiki](https://wiki.factorio.com/Replay_system) | ルールの互換性は受け取り時に確認し、盤面と得点はゲームの計算で取り直す。 |

## 3案

1. 短いIDを送り、サーバーへリプレイを置く。入力文字は少なくできるが、今のゲームにはサーバーがなく、公開と保存期限の運用が要る。
2. 完成した端末保存のJSONを送る。現在の再生へそのまま渡せるが、貼り付けには長い。開始条件や得点など、通常の共有に要らない項目も含まれる。
3. シード、受理された入力、終了tick、ルールの指紋を詰める。受け手が物理を計算する時間は掛かるが、サーバー不要で短くできる。これを選んだ。

形式3のルール指紋は再生の定数から作る値と同じ。旧形式2の数値の欄は、端末に保存済みの圧縮入力を読み戻すために引き続き扱う。数値しかない旧共有コードは互換性を照合できないので、共有から再生するときは版違いを返す。最長は端末保存・再生・共有で共通の1時間。

共有コードには得点を入れない。検査値はコピー中の破損を検出する。検査値を作り直し、ゲームが受理する入力を全部入れたコードは、その入力で実際に取れる得点の別プレイとして再現される。プレイヤーや出所を証明する仕組みはこの形式にはない。

形式3では、丸め済みのドラッグ速度を符号付き11ビットずつで格納する。ゲームが受理する現在の速度範囲をカバーし、どちらかが範囲外の入力は生の値の形式へ回す。152投すべてがドラッグの容量試験と、ゲームが実際に受理した操作の試験は別々に記録する。
