# 記録の作り直し（records）

## いま
- 版つきの詳しい統計（RunDetailV1）・別キー保存・移し替え・推移計算は実装済み。統合はリーダー待ち。
- 前回の失敗 2 件を直した: 到達 Tier は盤面の値と出来事が証明する Tier の大きい方
  （超新星の記録 = Tier 8 到達の証拠。counted() と同じ考え方に統一）、単発得点は出来事の
  記録をそのまま残す（合計得点で切り捨てると、欠けた盤面の入力で実績を失い、読み側の修復と
  矛盾して往復で値が変わるため）。
- つぎ: 出来事と盤面が矛盾する入力で「どちらを信じるか」の一貫性をもう一度総ざらいする。

## ファイルの分け方
- `stats.ts` …… 型・定数・出来事の数え上げ（fold）と仕上げ（buildRunDetail）。純粋な計算。
- `archive.ts` …… 読み値の検査（readRunDetail）、旧形からの移し替え（migrateStatsArchive / detailFromRecord）。
- `trend.ts` …… 直近 N 件 vs その前 N 件の推移（summarizeTrend）。全数値指標。
- `history.ts` …… 別キー `gravity-core:stats:v1` への保存（壊れた値の退避・拒否時のメモリ継続は save.ts と同型）。
- `recorder.ts` …… 1 tick ずつ出来事を受け取る蓄積器（出来事列を持ち越さなくてよい）。

## 決めた事と理由
- **出来事から数え、盤面からは集計値だけ取る。** 出来事の数と snapshot.stats が 1 対 1 に対応することを
  自動プレイの照合テストで固定した。maxChain は両方の大きい方（片方が欠けても残る）。
- **到達 Tier も同じ「大きい方」でそろえる。** 合体出来事は「生まれた Tier」（sourceTier + 1、
  resultTier があればそれも）、超新星は Tier 8 どうしの合体なので最上段到達の証拠。
  盤面の bestTierThisRun が欠けても出来事側から補える。実データではシムが合体のたびに更新するので
  両者は一致し、差が出るのは盤面だけが欠けた・壊れた入力。
- **単発得点は出来事の記録をそのまま残す（合計得点で切り捨てない）。** 盤面の得点が欠けた入力で
  起きた実績を失う上、読み側の修復が作り側の正規形を削ると往復で値が変わる。同じ理由で
  readRunDetail 側のクランプも外した。項目どうしの関係を直す修復は「作り側が保証する関係」
  （着地 ≤ 射出、内訳の合計 ≤ 合体数、限界超過 ≤ プレイ時間、超過時間があるなら回数 ≥ 1）に限る。
- **壊れた値は作る時にそろえる。** 無限の chain や範囲外の sourceTier をそのまま入れると、
  次回の読み込み検査で 1 回分まるごと落ちる。fold で正規化し、作った物は必ず readRunDetail を通ることを
  テストで確かめた。今回さらに: 限界出来事の時刻は `saneTick`（NaN・無限は捨て、負は 0 に丸める）、
  盤面の stats は `Partial` として読み、読めない playedAt は原点に置き換える。
  id だけは捏造しない（文字列でなければ空のまま → 保存時の検査で落ちる）。
- **読めない時刻の overLimitEnd は「来ない」と同じ扱い。** 区間を開いたままにし、仕上げで盤面の tick で閉じる。
  0 時刻に丸めて閉じると区間全体が消えて過小になるので、終了時刻まで越えていた扱い（過大側）に倒した。
- **限界区間は [0, 終了 tick] に切ってから和集合で足す。** 出来事の時刻が前後して区間が重なると
  素の和は実時間（極端には seconds 自体）を越えて膨らむ。和集合なら「実際に越えていた時間」に一致し、
  overLimitSeconds ≤ seconds が常に成り立つ。開きっぱなしの区間も [start, 終了 tick] として同じ潰しに乗せる。
- **限界超過は「越えていない→越えた」の遷移だけ数える。** 重複 start で区間も回数もずれない。
- **推移の best は窓の中の最大、allTimeBest は全期間の最大。** 「自己ベスト更新」を表示側が出せるように分けた。
  overLimitSeconds は小さいほど良い指標だが、比較は「値の最大」で統一し、解釈は表示側に任せる。
- **推移は全数値指標に出す。** 表示側が「何が伸びたか」を選べるように、RunDetailV1 の数値項目を全部対象にした。
  日時の読めない記録は位置が決まらないので比較から外す（保存値は検査済みなので通常は起きない）。

## リーダーへの依頼
- `src/app/app.ts` の `finishRun()` で統計の保存を繋げてほしい。部品は用意済み:
  `createStatsStore()`（別キー）と `createRunRecorder()`（`handleEvents` で受けた出来事を
  `recorder.feed(events)` に渡し、`finishRun` で `statsStore.add(recorder.finish(snap, meta))`。
  meta は `{ id: record.id, playedAt: record.playedAt, gameVersion: GAME_VERSION }`）。
  出来事列を配列で持ち越すなら `buildRunDetail(events, snap, meta)` でも同じ結果になる。
- 既存プレイヤーのランキング 10 件を統計へ移すなら
  `migrateStatsArchive({ version: 1, records: save.records })` を一度だけ `statsStore.save` に流す形で可能。

## 確かめていない事
- app.ts への実際の統合（リーダー担当のファイルのため手を出していない）。
- 1000 件上限の取り込み時の実機 localStorage 使用量（計算上は数百 KB の見込み）。
- `add` を 1 プレイごとに呼ぶと毎回全件の JSON を書き直す。1000 件時で数十 KB の再書き込みになるが、
  頻度はプレイ終了時の 1 回だけなので問題ない想定（実機では未計測）。
