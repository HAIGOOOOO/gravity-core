# このPCの自動作業の起動補正

2026-11-18、本人が3時間おきの自動作業を承認。

このPCのCodexでは、共有の `tools/auto-codex/run.ps1` が渡す `--full-auto` は「unexpected argument」で起動できない。`codex-compat.ps1` はその引数だけを、このCLIが受け付ける `--approve-for-me` へ読み替える。Windows PowerShellから `exec --full-auto --help` を渡して、正常にヘルプへ到達することを確認した。

さらに同じ起動補正で、ネットワークを有効にしたCodex CLIへ「作業・コマンド実行・ファイル変更はせず、起動確認の一言だけ返す」という診断を渡した。CLI v0.169.0-alpha.11.1から「起動確認済みです。」の応答を受け、終了コード0。これでログインと実際の応答まで確認した。通常の自動作業を1回完了したという意味ではない。

予約は共有の `setup.ps1 -Quiet` で登録し、同じ予約の `run.ps1 -Codex` に、この補正スクリプトの絶対パスを渡す。共有の停止印・重複防止・ログ・3時間間隔は同じ物を使う。

CLIの実行ファイルは通常PATHから探す。予約の環境に無い時のため、このPCで確認した実行ファイルのパスだけを `.git/gravity-core-codex-executable.txt` へ置く。このファイルは共有・コミットしない。認証情報は入れない。

停止は従来の `tools/auto-codex/stop.cmd`。PCが起動し、本人のWindowsセッションで実行できる時に動く。登録しただけでは、AIが実際の1回の作業を完了した確認にはならない。予約の実際の状態は `docs/progress/B.md` へ記録する。

リーダーへの依頼: 共有の予約スクリプトも、利用しているCLIの起動方法へ更新してほしい。この補正は担当BのこのPC用。
