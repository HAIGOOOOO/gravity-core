# 題目1・4周目：結果の待ち時間（差し戻し0）

## 調べた実物と3案

前回の3件を、今回は「何を待たせるか」という観点で再検討した。

- [Factorioの決定的な保存と復元](https://www.factorio.com/blog/post/fff-270)：途中保存から再開しても、観測できる結果が変わらないことを求める。今回も保存点は本物のsimulationのexportStateだけから作る。
- [Unity Timelineの再生操作](https://docs.unity.cn/Packages/com.unity.timeline@1.8/manual/tl-play-ctrls.html)：位置の指定と再生を区別する。結果一覧が出ることと、外部の記録を検証して再生できることを、別の段階として扱う設計に使う。
- [QuickTimeの再生操作](https://support.apple.com/en-sg/guide/quicktime-player/qtpa4808515d/mac)：見たい場面へ移る操作を結果に結び付ける。見どころの文だけで終えず、そのプレイのその時刻へ渡す。
- 実装の参照：[Worker](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers)、[MediaSource](https://developer.mozilla.org/en-US/docs/Web/API/MediaSource)。データの所有と受け渡し、部分的な準備を扱う際の参照。これらの作品が今回の方式を使っているという意味ではない。

案は①全部を再検証してから返す（既存）②プレイ中に出来事と保存点を記録しておく③未検証の結果を先に出す。②を選んだ。自分のプレイには既に本物の計算結果があるので、終了後に二度目の物理計算をする必要がない。③は改ざんされた結果を見せるため採用しない。

## 接続する形（リーダーへ）

```ts
const capture = createReplayCapture(seed);
const sim = capture.simulation; // 今のSimulationPortと同じ操作
// いつもどおりsubmitLaunch / stepFixed / getSnapshotを使う
const result = capture.finish();
// result.record / result.highlights / result.causeを結果画面へ
const replay = result.createPlayer(); // 再生するときだけ。同じ計算結果を使う
```

- 結果の整理は本物の出来事と盤面だけから行う。得点や物理を推測しない。
- 保存点は720を越えたら半分に間引く。初期の保存点は残す。入力と出来事は捨てない。
- 途中でfinishしてから続けても、前の結果の配列は増えない。同じ状態でfinishを繰り返す時は作り直さない。
- 受け取った保存や共有の文字列には、この経路を使わない。従来のparse→検証を通す。ページ間の受け渡しも、文字列へ戻して受け取る側で再検証する。
- 本体への接続はsrc/appの担当であるリーダーへ依頼する。既存createReplayPlayerに入力履歴を渡して行う全再検証の所要時間を、短縮したという変更ではない。

## 計測

- Node 22.23.3、Windows。6分間、8秒ごとに投入を続ける45投の記録で、結果整理0.63ms。全再検証1107ms、同期プレイヤー準備1079ms（同じ実行の比較）。
- 上記の後に同じ側へ連投して終了した417.91秒・161投の記録：結果整理0.34ms、保存点を間引いた後のseek5.02ms。結果の見どころ・原因・最終盤面は独立した全再検証と一致した。結果整理2秒以内とseek200ms以内を試験で要求している。
- Edge headless・390px幅：結果の整理2.6ms、最初の表示入口では受信まで3.1msだった。計測を改善し、レイアウト・盤面描画と描画の機会をまたぐ形に変更した後は、結果ボタンから表示まで45.5ms。
- 本物のスマートフォン、人間が6分遊んだ記録、遅い端末は未確認。加速してプレイを作る時間を、終了後の結果表示時間へ混ぜていない。実際に画面が更新されるまでの測定には描画の機会を含める。

## 審査と修正

- 初見役：結果からのリンクで別の30秒見本が開く→同じ記録を受け渡す。中止で前の結果を失う→新しい記録が完成するまで保持。敗因の対象が不明→白い輪・矢印と、その時刻へのリンクを追加。
- 見どころはそれぞれの時刻へ進める。別タブで開くことを明記し、元の結果を残す。ページ間のデータは受け取る側で検証する。
- 落とす役の確認と修正は進捗へ記録する。
