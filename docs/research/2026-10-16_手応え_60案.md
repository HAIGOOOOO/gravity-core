# GRAVITY CORE — Game Feel / Juice 徹底設計案

実在ゲームの開発者資料・講演・実装コードを参考にした演出提案集

結論：GRAVITY COREで最も伸ばすべきなのは、エフェクトの派手さよりも「物理的な納得感」「成功への期待」「連鎖の高揚」「危険の緊張」を一連の体験としてつなぐこと。

既に決まっている演出はかなり充実しているので、今回はそれらの焼き直しを避け、別の役割を持つアイデアを中心に提案する。

## 2. 提案の読み方と数値の前提

以下の数値は他作品から抽出した実測値ではなく、GRAVITY COREで最初に試すための設計目安。実装後にプレイテストで調整することを前提としている。

- 時間：ms＝ミリ秒。16.7msが60fpsの約1フレーム。
- 距離：pxは基準盤面直径600pxにおける論理ピクセル。スマホでは盤面直径に比例して縮小する。
- 強さ：拡大率は1.0が通常、1.05が5%拡大。αは透明度で0〜1。
- 参考：「作品名＋リンク」は着想元。独自案には「独自設計」と明記する。
- 注意：各案は単体で調整する。全部の最大強度を同時に有効化する設計は推奨しない。

特に重要なのは、物理挙動、演出の時間、画面の描画を別々に管理すること。見た目を派手にしても、天体の合体条件や衝突判定が不正確にならない構成が必要になる。

## 3. 具体的な演出アイデア 60選

### A. 投下・照準・物理の触り心地（1〜8）

ここでは、プレイヤーが「狙った」「投げた」「ちゃんと重力で動いた」と感じるための工夫を扱う。

1\. 予測軌道の粒子化

照準線を単なる線ではなく、等時間間隔に配置された小さな光点で表示する。核に近づくほど点の間隔が変わり、重力による加速が直感的に伝わる。

- 場面： 引いて投げる照準中
- 目安： 20〜32点、予測1.0〜1.5秒、点のα 0.2〜0.65
- 参考： [Angry Birds Spaceの重力軌道](https://www.pcworld.com/article/470176/angry_birds_space_review_an_amazingly_fun_innovative_take_on_the_familiar_game.html?utm_source=chatgpt.com)
- 注意： 予測が実際と大きく違うと不信感につながる。ゲーム本体と同じ重力式を使う。

2\. 着弾予報マーカー

未来の接触地点に半透明の小さな円を置き、プレイヤーが狙いの精度を視覚的に判断できるようにする。接触後の複雑な挙動は予報しない。

- 場面： 投下直前
- 目安： 直径が天体の70〜100%、α 0.2〜0.35、更新30Hz
- 参考： [Angry Birds開発者インタビュー](https://www.theguardian.com/artanddesign/2016/feb/23/how-we-made-angry-birds?utm_source=chatgpt.com)
- 注意： 他の天体が動いて予測不能な場合は、マーカーを破線にして不確実性を示す。

3\. 初速を目盛りで見せる

引っ張り量を、投下地点を囲む扇形の目盛りとして表示する。発射前から「強く投げるとどうなるか」が理解できる。

- 場面： 引っ張り操作
- 目安： 5段階、最大角度70°、入力変化への追従30ms以内
- 参考： [Angry Birdsの直感的な入力設計](https://www.theguardian.com/artanddesign/2016/feb/23/how-we-made-angry-birds?utm_source=chatgpt.com)
- 注意： 目盛りは速度の案内にとどめ、複雑なUIを増やさない。

4\. 投下地点の反作用

投下時、外周の発射地点に小さな衝撃痕を残す。天体を押し出した反作用を表現し、投下そのものに小さな達成感を与える。

- 場面： 天体を離した瞬間
- 目安： 直径8〜25px、発生40ms、消滅140ms
- 参考： [Vlambeer：The Art of Screenshake](https://videohighlight.com/v/AJdEqssNZ-U?utm_source=chatgpt.com)
- 注意： 照準位置を隠さない。これは画面揺れではなく投下位置限定の演出。

5\. 投下予約バッファ

次の天体が操作可能になる直前の入力を短時間だけ記憶し、操作可能になった瞬間に照準を開始する。入力したのに反応しない感覚を減らす。

- 場面： 連続して天体を投下する際
- 目安： 先行入力を80〜120ms保持、離した入力を勝手な投下に変換しない
- 参考： [Celeste開発者によるゲームフィール解説](https://threadreaderapp.com/thread/1238338574220546049.html?utm_source=chatgpt.com)
- 注意： 予約は照準開始まで。投下位置や物理を勝手に補正しない。

6\. 接線方向の速度サイン

投げた天体の周囲に短い速度マーカーを描く。曲げて投げたときに、核へ向かう運動と核の周囲を回る運動の違いが分かる。

- 場面： 投下後の飛行
- 目安： 2〜3本、4〜16px、寿命180ms、速度に比例
- 参考： [Angry Birds Spaceの軌道表現](https://www.pcworld.com/article/470176/angry_birds_space_review_an_amazingly_fun_innovative_take_on_the_familiar_game.html?utm_source=chatgpt.com)
- 注意： 常時矢印を出すのではなく、高速移動のときだけ出す。

7\. 側面摩擦の細かな火花

天体が山の表面を滑りながら転がるとき、接触点から細い火花や粉塵を出す。着地時の大きな変形とは別に、持続的な摩擦を伝える。

- 場面： 天体どうしが接触しながら滑走する際
- 目安： 相対接線速度が閾値以上で2〜5粒子/秒、寿命100〜220ms
- 参考： [Juice It or Lose It](https://www.gdcvault.com/play/1016487/juice-it-or-lose?utm_source=chatgpt.com)
- 注意： 静止した山から粒子が出続けると、落ち着かない画面になる。

8\. 物理的な安定への着地

山がほぼ静止すると、細かい運動マーカーや粉塵が自然に消えていく。何も起きていない状態にも明確な落ち着きを作る。

- 場面： 投下後に山全体が安定するとき
- 目安： 低速状態が250ms継続すると、補助演出を200msで減衰
- 参考： [Designing Game Feel：物理的一貫性の研究](https://researcher.itu.dk/p/en/research-outputs/designing-game-feel-a-survey?utm_source=chatgpt.com)
- 注意： 物理演算を無理に止める必要はない。表示だけを落ち着かせる。

### B. 合体・連鎖・得点の気持ちよさ（9〜16）

このパートは、既存の「吸い付き」「白フレーム」「スコア飛翔」を補完するもの。合体の結果をどれだけ価値ある出来事として感じさせるかが主題になる。

9\. 新生天体のシルエット先出し

合体した位置に、次の段階の天体の暗い輪郭を先に0.04秒だけ出し、その中に新しい模様や色が現れる。単なる置換ではなく「生まれた」と感じさせる。

- 場面： 通常合体の直後
- 目安： シルエット40ms、模様の展開80〜140ms
- 参考： [Threes!の合体演出に関する開発記録](https://asherv.com/threes/threemails/?utm_source=chatgpt.com)
- 注意： 合体後の当たり判定は即座に有効化し、描画の完了を待たせない。

10\. 段階ごとの誕生モチーフ

9段階それぞれに固有の小さな誕生演出を割り当てる。低段階は丸い欠片、高段階は放射状の模様など、色だけでなく形でも段階の違いを伝える。

- 場面： すべての通常合体
- 目安： 低段階3〜5個、高段階8〜12個の図形、持続150〜350ms
- 参考： [Threes!制作記録：個々のタイルの個性](https://www.asherv.com/threes/threemails/?utm_source=chatgpt.com)
- 注意： 9種類を全部派手にしない。高段階ほど情報量を増やす。

11\. 合体元の残留痕

消えた2つの天体の位置に、ごく短時間だけ光の輪郭を残す。合体後の天体の周囲に「何が合体したのか」という履歴が見える。

- 場面： 合体直後
- 目安： 残留80〜180ms、α 0.25→0、線幅1〜2px
- 参考： [Vlambeer：Permanence（出来事の痕跡）](https://videohighlight.com/v/AJdEqssNZ-U?utm_source=chatgpt.com)
- 注意： 同時合体では最大4組程度に制限する。

12\. 連鎖可能時間の可視化

新しく生まれた天体の外周に、2.5秒で消える細い時計リングを付ける。プレイヤーは連鎖できる残り時間を数字を読まずに把握できる。

- 場面： 合体後、連鎖猶予中
- 目安： 2,500ms、線幅2〜3px、残り500msで色を変化
- 参考： [Candy Crush Saga公式：連鎖の仕組み](https://candycrush.zendesk.com/hc/en-us/articles/211939745-What-are-Sweet-cascades?utm_source=chatgpt.com)、独自UI
- 注意： 連鎖判定に実際に使うゲーム内時刻と同期する。時計の見た目だけ遅れないようにする。

13\. 連鎖段階に応じた演出の解禁

1連鎖目は小さな演出、3連鎖目で新しい図形、5連鎖目で特別な色彩表現を解禁する。通常合体との報酬の差が明確になる。

- 場面： 連鎖数が一定値を超えた瞬間
- 目安： 3・5・8連鎖を節目に、演出強度を1.0→1.35→1.7倍
- 参考： [Candy Crush Saga：Sweet Cascades](https://candycrush.zendesk.com/hc/en-us/articles/211939745-What-are-Sweet-cascades?utm_source=chatgpt.com)
- 注意： 段階が上がるたびに演出を全部重ねるのではなく、置き換える。

14\. 連鎖名の格上げ

倍率数字とは別に、連鎖の進行を短い称号で見せる。例えば「CHAIN」「ORBITAL」「NOVA CHAIN」など、達成の質が変わったように感じられる。

- 場面： 3・5・8連鎖の節目
- 目安： 180msで出現、400〜650ms保持、150msで退場
- 参考： [ぷよぷよ通の開発者インタビュー](https://shmuplations.com/puyopuyotsu/?utm_source=chatgpt.com)、[Candy Crushの連鎖称号](https://candycrush.zendesk.com/hc/en-us/articles/211939745-What-are-Sweet-cascades?utm_source=chatgpt.com)
- 注意： 毎回文字を出すとプレイ中の視線を奪う。重要な節目だけに限定。

15\. 得点計算の内訳を刻む

飛んでいく得点とは別に、連鎖の途中で「基本点 × 連鎖倍率」を小さな帯に記録する。何が得点を大きくしたのかを見せる。

- 場面： 連鎖が発生したとき
- 目安： 新規内訳を1件あたり70〜110msで追加、最大3件表示
- 参考： [Balatro開発者インタビュー](https://www.washingtonpost.com/entertainment/video-games/2024/09/26/balatro-mobile-release-localthunk-interview/?utm_source=chatgpt.com)
- 注意： 数字を読む必要がない人には邪魔になりやすい。高倍率時だけ表示してもよい。

16\. 連鎖完了の「決着印」

2.5秒の猶予が終了した際、連鎖結果を一度だけ確定させる小さなエンブレムを表示する。長い連鎖が終わったという達成感を生む。

- 場面： 連鎖終了時
- 目安： 出現120ms、保持300ms、消滅200ms
- 参考： [Peggle：成功演出の区切り](https://www.pcgamer.com/the-making-of-peggle/2/?utm_source=chatgpt.com)
- 注意： 連鎖終了まで次の操作を止めない。

### C. 「時間」を使った手応え（17〜24）

既存のヒットストップと連鎖スローに加えて、時間をどう配分するかという視点の提案。

17\. 大合体後の無演出時間

大きな合体が完了した直後、ごく短時間だけ新しい装飾的エフェクトを抑制する。派手な瞬間の後に静寂を作ることで、直前の出来事が際立つ。

- 場面： 7〜9段階の合体後
- 目安： 装飾エフェクトを100〜160ms抑制
- 参考： [Tetris Effect開発者インタビュー](https://www.unrealengine.com/developer-interviews/how-tetris-effect-became-a-modern-work-of-art?utm_source=chatgpt.com)
- 注意： 天体の動き、危険表示、操作反応は止めない。

18\. 同時合体の階段状演出

複数の合体が同一フレームに起きた場合、物理判定は同時のまま、装飾的な光や得点表示だけ少しずらす。瞬間的な大量発光を、認識できる連続的な出来事へ変える。

- 場面： 同時に3組以上合体したとき
- 目安： 表示開始を25〜45msずつずらし、全体の遅延上限120ms
- 参考： [Balatroの段階的得点フィードバック](https://www.washingtonpost.com/entertainment/video-games/2024/09/26/balatro-mobile-release-localthunk-interview/?utm_source=chatgpt.com)
- 注意： 天体の出現・衝突判定を遅延させない。

19\. 危機突入時の一度だけの緩急

核熱量が高い閾値を初めて超えたとき、危険を認識させる短い時間演出を入れる。連続して発生させず、一度の警告として扱う。

- 場面： 核熱量が85に到達した瞬間
- 目安： 演出時計を100ms程度0.65倍速、同一危機につき1回
- 参考： [Peggleの時間演出](https://patents.justia.com/patent/8678904?utm_source=chatgpt.com)を逆の感情に応用
- 注意： 既存の敗北停止とは別。物理を遅くするなら猶予時間も公平に扱う必要がある。

20\. 連鎖開始のリズム確立

最初の3回の連鎖について、演出の開始間隔を一定のテンポに近づける。発生タイミングそのものを変更せず、光やUIのアニメーションでリズムを作る。

- 場面： 連鎖序盤
- 目安： 視覚演出を80〜120msの単位で整理、補正遅延は最大30ms
- 参考： [Lumines開発者インタビュー](https://news.halloffame.workers.dev/2018/7/13/17567768/lumines-remastered-interview-tetsuya-mizuguchi?utm_source=chatgpt.com)
- 注意： 実際の合体が不規則なのに、規則正しい演出だけ強制するとズレが目立つ。

21\. 連鎖終盤のテンポ圧縮

短い間に合体が連発する場合、個々の演出の余韻を短くして重なりを減らす。連鎖が加速しているように感じさせながら、画面の混雑を防ぐ。

- 場面： 0.8秒以内に4回以上の合体
- 目安： 粒子寿命を通常の65〜75%、UI保持時間を80%へ
- 参考： [Tetris Effectの興奮・緩和設計](https://www.unrealengine.com/developer-interviews/how-tetris-effect-became-a-modern-work-of-art?utm_source=chatgpt.com)
- 注意： 物理演算自体を早送りして、意図しない合体を誘発しない。

22\. 読み取り時間の確保

大きな天体が誕生したとき、重要な輪郭と種類が認識できるまで、装飾エフェクトがその天体を覆わないようにする。プレイヤーは次の一手を考えやすくなる。

- 場面： 高段階の合体
- 目安： 誕生後100〜150msは輪郭の視認性を優先
- 参考： [Picross開発元JupiterのUI設計インタビュー](https://www.videogameschronicle.com/features/picross-developer-jupiter-on-nearly-30-years-of-puzzling-prowess/?utm_source=chatgpt.com)
- 注意： 飛行中の天体を消したり、判定を遅らせたりしない。

23\. 超新星後の余韻だけ早送り

超新星による大きな演出の後、残っている光や粉塵のアニメーションだけを速く消して、通常プレイへ戻す。爆発の迫力とテンポの良さを両立する。

- 場面： 超新星の反動が収まった後
- 目安： 残留エフェクト時計を180〜250msだけ1.5〜2.0倍速
- 参考： [Vlambeer：Slow Motionと演出の緩急](https://videohighlight.com/v/AJdEqssNZ-U?utm_source=chatgpt.com)
- 注意： 天体そのものを早送りしてはいけない。

24\. 連鎖後の自然な復帰

連鎖終了時に、スロー状態から一瞬で通常速度へ切り替えず、滑らかに戻す。カクッと速度が切り替わる違和感を抑える。

- 場面： 連鎖スローが終了するとき
- 目安： 0.85倍速→1.0倍速を120〜180msで補間
- 参考： [Tetris Effectの時間・視覚演出](https://www.unrealengine.com/developer-interviews/how-tetris-effect-became-a-modern-work-of-art?utm_source=chatgpt.com)
- 注意： これは既存スローの調整案。新しいゲームルールを追加する必要はない。

### D. カメラ・奥行き・変形（25〜32）

画面全体を振る以外にも、物体の重さや空間の奥行きを伝える方法は多い。

25\. 合体位置への局所的な寄り

大きな合体の位置を、短時間だけ構図の中心寄りに見せる。カメラ全体を動かすのではなく、背景の装飾層だけをわずかに引き寄せてもよい。

- 場面： 6〜8段階の合体
- 目安： カメラ移動2〜6px、寄り100ms、復帰160ms
- 参考： [Peggleのズーム演出](https://patents.justia.com/patent/8678904?utm_source=chatgpt.com)
- 注意： プレイヤーが照準中なら無効化。核の物理座標は固定する。

26\. 投下方向へのカメラ先読み

天体を発射した直後、カメラの構図を移動方向へごくわずかに寄せる。プレイヤーが投げた勢いを、背景との相対移動でも感じられる。

27\. 回転の慣性を感じる構図

横方向に大きな運動が発生した場合、背景層だけがわずかに回転して遅れて戻る。回転した物体の勢いを空間全体の反応として表す。

- 目安： 背景回転±0.3〜0.6°、復帰250ms

28\. 重さに応じた接触影

天体どうしが接している部分に、薄い接触影を表示する。球体が単なる円の集合ではなく、実際に重なり合って積まれているように見える。

- 場面： 天体が山を形成しているとき
- 目安： 接触点を中心に4〜12pxの暗いグラデーション、α 0.08〜0.2

29\. 新生天体の内部ゼリー振動

合体で生まれた天体の内部模様だけが、一瞬遅れて揺れる。表面の拡大縮小とは違い、内部に柔らかい質量があるように感じさせる。

速度が高い天体だけに、進行方向と逆側へ半透明の残像を残す。投下の勢いを表し、遅い天体との速度差を際立たせる。

37\. 加算合成による小さな光源

通常の光は柔らかいグラデーションで描き、重要な瞬間にだけ加算合成で重ねる。重なった部分が明るくなり、光が集中した感覚を作れる。

39\. 粒子が重力で曲がる

合体で出た装飾粒子を、単純な直線運動ではなく核へ向かう加速度で曲げる。ゲームの基本原理とエフェクトが一致する。

57\. 超新星の破片が作る一時的な環

超新星後に残った装飾粒子が、核の周囲を一時的に周回し、細い土星の環のような模様を作る。爆発後も宇宙空間に物理的な余韻が残る。

- 場面： 超新星の爆風が収まった後
- 目安： 20〜35粒子、環形成300ms、消滅800〜1,500ms
- 参考： 独自設計（土星の環・降着円盤からの着想）
- 注意： 既存の天体が吹き飛んで戻る挙動とは別の装飾粒子として実装する。

58\. 核熱量低下時の冷却結晶

核熱量が大きく低下したとき、一時的に核の周囲へ小さな結晶模様が現れて溶ける。回復を単なるゲージ変化ではなく、盤面の状態変化として感じさせる。

- 場面： 例えば熱量80以上から50以下まで回復した際
- 目安： 6〜10個の結晶、出現180ms、保持300ms、消滅250ms
- 参考： 独自設計（熱量と相変化のモチーフ）
- 注意： 「冷却したから特殊効果が発生した」と誤解させない。報酬効果を付けないなら短い装飾にとどめる。

59\. 安定軌道の細い輪

天体が短時間ほぼ同じ半径を保って核を周回すると、薄い軌道の輪郭を表示する。重力を利用してうまく投げられたことが、視覚的に伝わる。

- 場面： 一定時間、安定した周回軌道になったとき
- 目安： 半径変動が0.5秒間で5%以内なら表示、α 0.1〜0.2
- 参考： 独自設計、[Angry Birds Spaceの軌道物理](https://www.pcworld.com/article/470176/angry_birds_space_review_an_amazingly_fun_innovative_take_on_the_familiar_game.html?utm_source=chatgpt.com)
- 注意： 偶然の一瞬の円運動で表示しない。周回の条件を満たしたときだけ。

60\. 円形配置が作る共鳴紋様

同じ段階の天体が核の周囲に対称的に並ぶと、核の背景に幾何学的な模様が浮かび上がる。円形盤面ならではの、配置自体に美しさを感じさせる仕掛け。

- 場面： 3つ以上の同段階天体がほぼ等角度で配置されたとき
- 目安： 角度誤差±12°以内、判定持続250msで出現、紋様は400msで消える
- 参考： 独自設計（対称性・軌道共鳴のモチーフ）
- 注意： 特別なボーナスがない場合は、得点が発生するような演出にしない。装飾であることを区別する。

## 4. 時間演出の実装パラメータ

個別の演出だけでなく、時間の全体設計をまとめておく。

### ヒットストップの目安

すでに採用が決まっているヒットストップについては、次のような段階分けから調整するのがおすすめ。

| 合体の規模    | 停止時間の初期値 | 復帰        |
| -------- | -------- | --------- |
| 低段階（1〜3） | 0〜17ms   | 即時        |
| 中段階（4〜6） | 17〜33ms  | 即時        |
| 高段階（7〜8） | 33〜50ms  | 80msで演出減衰 |
| 最高段階への合体 | 50〜67ms  | 100〜150ms |
| 超新星      | 既存演出で別管理 | 専用の演出曲線   |

これらは60fpsを想定した目安。毎回ゲーム全体を物理的に停止させるという意味ではない。小さな合体で重いヒットストップを繰り返すと、パズルとしてのテンポが悪くなる。

### おすすめの1回の大型合体シーケンス

合体判定を t=0 とした演出タイムライン

合体確定

t = 0ms

新生天体の輪郭

0〜40ms

ヒットストップ

0〜50ms

模様・色の展開

40〜140ms

局所発光

0〜180ms

スケールは概念図。物理的な合体と次の衝突判定は演出の完了を待たない。

最も大切なのは、次の合体が発生しても前の演出の終了を待たないこと。

GRAVITY COREは、山が重力で動き続け、連鎖が自然発生するゲーム。アニメーションが物理処理を待たせる設計にしてしまうと、最も重要な連鎖の気持ちよさが損なわれる。

### 時間を管理する際の設計ルール

| 時間の種類   | 管理対象                 | おすすめ        |
| ------- | -------------------- | ----------- |
| 物理時間    | 天体の位置、速度、衝突          | 固定ステップ 60Hz |
| ゲーム進行時間 | 連鎖猶予2.5秒、核熱量など       | 物理と整合する時計   |
| 演出時間    | 発光、残像、UI、粒子          | 個別の時計・倍率    |
| 実時間     | 入力受付、ポーズ処理、パフォーマンス計測 | 壁時計で管理      |

連鎖猶予の2.5秒は、演出時計ではなくゲーム進行時間に基づいて測ると整合を取りやすい。例えば物理的なスロー中だけ連鎖猶予が実時間で短くなると、不公平に感じられる。

特に、既存の「合体を必ず行う」ルールは最優先。演出の都合で同じ種類が接触しているのに合体しない状態を作らないようにする。

例えば発光は、毎フレーム `shadowBlur` を多数回使うより、小さな光スプライトを使い回す方法を優先したい。

```

function createGlowSprite(size = 64): HTMLCanvasElement {
  const canvas = document.createElement("canvas");
  canvas.width = size;
  canvas.height = size;

  const ctx = canvas.getContext("2d")!;
  const r = size / 2;

  const gradient = ctx.createRadialGradient(
    r, r, 0,
    r, r, r
  );
  gradient.addColorStop(0, "rgba(255,230,160,1)");
  gradient.addColorStop(0.25, "rgba(255,150,50,0.45)");
  gradient.addColorStop(1, "rgba(255,100,30,0)");

  ctx.fillStyle = gradient;
  ctx.fillRect(0, 0, size, size);
  return canvas;
}

const glow = createGlowSprite();

// 合体時に呼ぶ。alpha は 0〜1
function drawGlow(
  ctx: CanvasRenderingContext2D,
  x: number, y: number,
  radius: number,
  alpha: number
) {
  ctx.save();
  ctx.globalCompositeOperation = "lighter";
  ctx.globalAlpha = alpha;
  ctx.drawImage(
    glow,
    x - radius, y - radius,
    radius * 2, radius * 2
  );
  ctx.restore();
}

```

これなら比較的簡単に、通常合体、連鎖、大型天体の発光を共通化できる。

ただし、Canvas 2Dの`filter`はブラウザによって対応差があるため、重要な演出を`ctx.filter = "blur(...)"`だけに依存させない方が安全。

### なぜこの順番なのか

1位：連鎖可能時間の可視化

2.5秒というルールは、プレイヤーが認識できるほど価値が上がる。残り時間が目で分かると、連鎖を狙う意欲と成功時の納得感が強まる。単なる装飾ではなく、ゲーム自体を改善できる点で最優先。

2位：限界リングの危険角度表示

核熱量は数字で把握できても、具体的にどこが危険なのかは円形盤面だと分かりにくくなりやすい。危険の方向を示すだけで「山を救う」判断がしやすくなる。

3位：予測軌道の粒子化

このゲームは単純に落とすだけでなく、曲げて投げられることが特徴。加速や曲射を気持ちよく見せることは、ゲームの最も独自性のある操作を強化することになる。

4位：新生天体のシルエット先出し

天体の誕生を認識するための40ms程度の工夫。既存の派手な合体エフェクトを邪魔せず、完成度を一段階上げやすい。

5位：連鎖段階に応じた演出解禁

連鎖の回数によって視覚的な価値が変わる。大きな連鎖を目指す動機を作り、通常の合体と高連鎖の差を明確にできる。

6位：新生天体の内部ゼリー振動

GRAVITY COREの主役は丸い天体。外輪郭だけでなく内部に遅れた動きを作ると、球体そのものが魅力的になる。細かいが、繰り返し見る合体に効く。

7位：同時合体の階段状演出

大量の合体を単なる一瞬の光にしないための工夫。特に連鎖が発展したとき、何が起きたかを順に認識できる。

8位：重力の等高線

ゲーム名の「GRAVITY」を目に見えるものにできる点で価値が高い。重力操作を今後追加するなら、先に用意しておきたい表現。

9位：粒子が重力で曲がる

演出と物理法則が一致しているため、安価な装飾でも世界観を強められる。合体・超新星など多数の場面で再利用できる。

10位：大合体後の無演出時間

新しい光や粒子を足さず、あえて引き算する工夫。既に多くのエフェクトが採用されているGRAVITY COREでは、むしろ費用対効果が高い可能性がある。

## 最後に：GRAVITY COREで目指すべき気持ちよさ

GRAVITY COREは、既存のスイカゲーム系パズルと比べて、天体が中央重力に引かれながら積もり、回転し、自然に連鎖するという強い個性を持っている。

だから、単純に発光や揺れを増やしても、その個性は十分に活かせない。

狙うべき体験は次の流れ。

投下前には軌道から未来が想像できる。投下後には重力に引かれる納得感がある。合体では新しい天体の誕生に重量感がある。連鎖では次の成功を期待し、達成のたびに盛り上がる。危機では山の圧迫感を見ただけで焦りを感じ、回復では緊張が解ける。

この流れが成立したうえで、超新星という最大級のイベントを際立たせるのが理想。

特にGRAVITY COREは、既に多数の強い演出が決まっている。だから今後は、さらに演出を追加することと同じくらい、どの瞬間には何も起こさないかを設計することが重要になると思う。
