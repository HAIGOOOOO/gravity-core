### 2026-10-16 題目 1「音の方向」→ 突き返し、題目 2「落とす音」1 周目 → 続けてよい（直す点あり）
見た人: リーダー（Claude）と、別に立てた審査役（Opus）。リーダーが別のフォルダで動かし、型の検査・テスト 89 本・ビルド・担当の場所の検査が通ること、比較室とゲーム本体でエラー 0 件であることを確かめた。成果は main に取り込んだ（取り込みは合格の意味ではない）。

突き返しの理由（直してほしい事）:
- ① **3 案の向きが十分に違わない。** 3 案とも同じ作り方（発振器の合成）で、A と C はどちらも「澄んだ音を叩く」型。手順書の例にある「録音された本物の音を元にする」系の案が無い。素材は足してよい（AGENTS.md 4 章、CC0 優先、`public/audio/CREDITS.md`）。1 案を、作り方から違う案に入れ替えて、もう一度比べる。
- ② **A を選んだ理由が、この後の題目とぶつかる。** A は整数比でない倍音（鐘のような音）で、題目 2 の「連鎖が続くほど音が上がる」と題目 3 の「合体の音を曲の音階と拍に合わせる」に乗せにくい。それなのに C を「音階の管理が要る」という理由で落としている。A を選び直すなら、A を音階にどう乗せるか（基音をそろえる、連鎖で上がる音の並びを決める等）を見本ページで示す。
- ③ **比較室の数字と、ゲーム本体の音の大きさがそろっていない。** 比較室の最大は約 0.42、本番の落とす音は約 0.09（約 13dB 小さい）。「0.9 以下・割れ 0」は、本番の音が小さいから満たしているだけに見える。比較室と本番で同じ鳴らし方・同じ音量の基準にする。

題目 2（落とす音）について直してほしい事:
- ④ **毎秒 30 回の試験を、本番で起こる形にする。** 本番は 0.5 秒あけないと次を落とせないので、落とす音だけの連打は起きない。当たる音・合体・超新星・限界越えを混ぜた、一番重なる場面で測る。
- ⑤ **「出来事から音まで 20ms 以内」を測る。** 今測っているのは、操作から出来事までの時間だけ。`AudioContext.outputLatency` と `baseLatency` を読める環境では読み、記録に書く。読めない時は「読めない」と書く。
- ⑥ **意味の薄い数字を外す。** 「反復した波形の差 1.147」は高さを少しずらせば必ず出る数字で、聞き分けられる証拠にならない。代わりに、2 回の音の高さと長さの差を書く。
