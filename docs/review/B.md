**突き返し 3（★★、本体へつなぐ前に必ず）**
1. `run-database.ts:11-25` の `indexedDB.open` に時間切れが無い。Safari で open が返らない不具合が出ると、`ready()` と `add()` が永久に返らず、結果と履歴が固まる。3 秒ほどで失敗扱いにする。
2. IndexedDB だけ使えない端末（localStorage は使える）で、状態が `unreadable` になり、保存が一切できない（`runs.ts:134,188,267-270`）。open の失敗の時だけ localStorage の道（writeQueue）へ切り替える。transaction の失敗では切り替えない。
3. IndexedDB を使っている間も、localStorage に最大 150 万文字の写しを書く（`runs.ts:190-199,261`）。Safari の 5MB は UTF-16 で数えるので、写しだけで約 3MB になり、`save.ts` の最高点と設定の書き込みが黙って落ちる。IndexedDB の間は写しを書かない（残すなら再生を抜いた形）。試験で「写しの後でも最高点が保存できる」を確かめる。

**ついでに（★、次の周でよい）**
- 4. 端末の時計が戻ると `playedAt` が古くなり、容量は足りているのに `tooLarge` で 1 件まるごと捨てる（`runs.ts:87-99,233-235`）。再生だけ外して保存し、理由を分ける。
- 5. 1 回書き込みに失敗すると、読めているのに `unreadable` が残る（`runs.ts:269`）。書けなかった時は `unsaved` などに分ける。
- 6. IndexedDB の間の `load()` は別タブの保存を拾わない。5 行の手順に「表示のたびに `await ready()`」を書き足す。
